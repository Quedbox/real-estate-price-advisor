# Real Estate Price Advisor

A reproducible machine-learning project that estimates the market price of a Russian real-estate listing and compares the estimate with its asking price.

The repository keeps exploratory analysis in Jupyter and puts data preparation, feature engineering, training, evaluation, and inference in reusable Python modules.

## Project structure

```text
real-estate-price-advisor/
|-- data/
|   |-- raw/                         # source CSV (download separately)
|   `-- processed/                   # cleaned data generated by the CLI
|-- modeling/

|   `-- figures/                     # EDA figures and generated model diagnostics

`-- uv.lock
```

## Data

The source is the Kaggle **Russia Real Estate 2018-2021** dataset. Download the source CSV separately and place it at `data/raw/real_estate_raw.csv`. The original data is not committed to this repository.

The preparation step parses listing timestamps, converts numeric columns, removes exact duplicates, and filters impossible values such as non-positive price or area, invalid floor relationships, and out-of-range coordinates. Missing kitchen area is retained. A row-count audit is written to `reports/cleaning_report.csv`.

Outlier review lives in the EDA notebook. The training pipeline does not filter rows by price-per-square-metre or target percentiles before splitting: using the target to decide which holdout rows survive would bias evaluation. Listings with missing timestamps remain available for EDA but are omitted from chronological model evaluation.

## Modeling approach

- `DummyRegressor` provides a reference point, and `Ridge` provides a regularized linear baseline with imputation and one-hot encoding.
- CatBoost is the main tree-based candidate. Region, building type, and object type are treated as categorical features.
- The model predicts `log1p(price)`; evaluation metrics are reported on the original RUB scale.
- Validation and holdout partitions are chronological and split at calendar-month boundaries. Model selection uses validation MAE. The later holdout is scored once after the selected model is refit on the development period.
- CatBoost early stopping uses RMSE on the log target; final candidate selection uses MAE in RUB on the validation period.
- A small weighted blend of the two best validation candidates is retained only when one of three predeclared weights improves validation MAE.
- Feature transformations are shared by training and inference. Asking price, timestamps, and price-per-square-metre are excluded from model inputs.
- The default run compares the median baseline, Ridge, and one CatBoost configuration. `--tune` runs a two-stage CatBoost search: a coarse depth/learning-rate grid, then a local search around its validation leader over depth, learning rate, L2 regularization, and random strength. Candidates use early stopping and are ranked by validation MAE. `--ablation` measures the contribution of location and time features.
- Tuning writes `reports/candidate_leaderboard.csv` and `reports/model_selection_summary.md`. The leaderboard records candidate parameters, early-stopping iterations, and validation metrics. The summary names the selected model and configuration, compares the best CatBoost candidate with its default configuration, and records the final holdout score. Since candidates share one validation window, small differences should be treated as tentative and confirmed on a later time split.
- All project figures use Matplotlib, and Plotly is excluded from the locked environment.

Reported metrics include MAE, RMSE, R2, MAPE, MdAPE, and WAPE. Holdout errors are also summarized across major region and property-type segments.

## Setup and usage

Install the locked environment with [uv](https://docs.astral.sh/uv/):

```bash
uv sync
```

Prepare the source data:

```bash
uv run python -m modeling.cli prepare
```

Train, select on validation, and create the final holdout reports:

```bash
uv run python -m modeling.cli train
```

Run the two-stage fine-tuning search and feature ablations:

```bash
uv run python -m modeling.cli train --tune --ablation
```

Estimate prices for a CSV containing the listing input columns. If the file includes `price`, the output also includes the asking-price gap and the `below_market`, `market_price`, or `above_market` label.

```bash
uv run python -m modeling.cli predict --input path/to/listings.csv --output reports/predictions.csv
```

Open `notebooks/01_eda.ipynb` from the repository root or the `notebooks/` folder to explore the cleaned data. The notebook does not train models.

## Outputs

Training creates `models/best_model.joblib` and writes the selected-model metadata, candidate leaderboard, model-selection conclusions, validation/holdout metrics, predictions, segment diagnostics, feature importance, and Matplotlib figures under `reports/`.

`reports/archive/initial_experiment/` preserves the first notebook-based experiment and its published outputs. Those metrics were produced before the current validation/holdout protocol and are retained for project history; rerun the CLI to create current results.

## Limitations

The estimate reflects relationships in listings from 2018-2021 and should not be presented as a current appraisal without recent data and fresh validation. Re-listed properties can also recur at different dates because the source does not provide a stable property identifier.

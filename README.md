# Real Estate Price Advisor

Воспроизводимый ML-проект для оценки рыночной стоимости объявления о продаже недвижимости в России. Модель оценивает ожидаемую цену, сравнивает её с ценой объявления и помогает выделять варианты ниже или выше предполагаемого рынка.

Исследовательская часть оставлена в Jupyter Notebook, а подготовка данных, feature engineering, обучение, валидация и инференс вынесены в переиспользуемые Python-модули.

## Данные и очистка

Используется датасет Kaggle **Russia Real Estate 2018–2021**. Исходный файл нужно скачать отдельно и положить в `data/raw/real_estate_raw.csv`.

Команда подготовки данных:

```bash
uv run python -m modeling.cli prepare
```

Подготовка:

- преобразует числовые поля и временные признаки;
- удаляет полные дубликаты;
- отбрасывает записи с невалидной ценой, площадью, этажами, кухней или координатами;
- сохраняет пропуски в площади кухни и делает отдельный индикатор пропуска;
- записывает аудит количества строк в `reports/cleaning_report.csv`.

Целевые выбросы не удаляются автоматически перед разбиением. Фильтрация по цене за квадратный метр или по процентилям цены могла бы использовать target и исказить оценку на validation/holdout. Анализ распределений и выбросов находится в `notebooks/01_eda.ipynb`.

## Подход к моделированию

- Целевая переменная преобразуется как `log1p(price)`, а метрики считаются в исходных рублях.
- `DummyRegressor` служит простой точкой отсчёта.
- `Ridge` используется как регуляризованный линейный baseline с импутацией, масштабированием и one-hot encoding.
- CatBoost обрабатывает `region`, `building_type` и `object_type` как категориальные признаки.
- Добавлены признаки доли кухни, площади на комнату, отношения этажа к этажности, первого/последнего этажа, студии и циклического месяца публикации.
- `price`, исходные временные строки и `price_per_m2` исключены из входов модели, чтобы не допускать утечку target.
- Разбиение выполняется по календарным месяцам в хронологическом порядке: train → validation → holdout.
- Кандидаты выбираются по MAE на validation. Holdout используется один раз после выбора и переобучения модели на train + validation.
- Для CatBoost используется early stopping по RMSE на логарифмированной цене.
- Проект использует Matplotlib; SQL и Plotly в пайплайн не добавлялись.

Для отдельного запуска подбора параметров доступны coarse- и fine-tuning CatBoost:

```bash
uv run python -m modeling.cli train --tune --ablation
```

В этом режиме сравниваются глубина и learning rate, затем параметры уточняются вокруг лучшего кандидата. Результаты сохраняются в `reports/candidate_leaderboard.csv` и `reports/model_selection_summary.md`.

## Зафиксированные результаты запуска

Ниже приведены результаты из `reports/model_selection_summary.md`, `reports/model_metrics.csv` и `reports/model_metadata.json`.

Команда зафиксированного запуска была выполнена без `--tune` и `--ablation`:

```bash
uv run python -m modeling.cli train
```

Всего в хронологическом эксперименте использовано 5 470 541 объявление:

| Часть | Период | Объявления |
|---|---|---:|
| Train | 2018-02-19 — 2020-05-31 | 3 807 801 |
| Validation | 2020-06-01 — 2020-11-30 | 973 532 |
| Holdout | 2020-12-01 — 2021-05-01 | 689 208 |

Победителем стал базовый `CatBoostRegressor`:

```text
depth=8
iterations=1200
learning_rate=0.05
l2_leaf_reg=5.0
random_strength=1.0
random_state=42
```

### Сравнение кандидатов на validation

| Кандидат | MAE, RUB | RMSE, RUB | R² |
|---|---:|---:|---:|
| CatBoost | 972 328 | 7 491 129 | 0.4621 |
| Blend CatBoost + median, 75/25 | 1 260 544 | 7 856 713 | 0.4084 |
| Blend CatBoost + median, 50/50 | 1 742 100 | 8 515 241 | 0.3050 |
| Blend CatBoost + median, 25/75 | 2 293 614 | 9 405 380 | 0.1521 |
| Dummy median | 2 868 843 | 10 468 214 | -0.0503 |
| Ridge | 28 901 709 | 15 446 854 373 | -2 286 908.9274 |

CatBoost снизил validation MAE примерно на 66,1% относительно медианного baseline. Ни один из проверенных blend-вариантов не улучшил результат CatBoost, поэтому в итоговый артефакт сохранён именно он.

### Итоговая оценка на временном holdout

После выбора модель была переобучена на train + validation и проверена на более позднем holdout:

| Метрика | Значение |
|---|---:|
| MAE | 1 450 474 RUB |
| RMSE | 7 609 150 RUB |
| R² | 0.5209 |
| WAPE | 23.88% |
| MdAPE | 18.33% |
| MAPE | 1 212.44% |

Высокий MAPE объясняется чувствительностью процентной ошибки к объявлениям с очень низкой ценой и экстремальными ошибками. Поэтому для этого запуска более устойчивыми ориентирами являются MAE, RMSE, WAPE и MdAPE. Разница между validation MAE и holdout MAE также показывает, что качество меняется на более позднем временном периоде.

Текущие выводы относятся к данному датасету и выбранным временным окнам. Перед использованием модели для актуальной оценки рынка нужны свежие данные и новая временная валидация.

## Установка и запуск

Установка зафиксированного окружения через [uv](https://docs.astral.sh/uv/):

```bash
uv sync
```

Полный базовый сценарий:

```bash
uv run python -m modeling.cli prepare
uv run python -m modeling.cli train
```

Оценка новых объявлений:

```bash
uv run python -m modeling.cli predict \
  --input path/to/listings.csv \
  --output reports/predictions.csv
```

Если во входном файле есть `price`, результат также содержит отклонение от прогнозной цены и одну из меток `below_market`, `market_price` или `above_market`. Порог по умолчанию составляет ±15% и может быть изменён через `--threshold-percent`.

Ноутбук `notebooks/01_eda.ipynb` предназначен для просмотра EDA. Обучение моделей из ноутбука не выполняется.

## Артефакты

После обучения создаются:

- `models/best_model.joblib` — выбранный bundle модели и логика Price Advisor;
- `reports/model_metrics.csv` — метрики кандидатов и итогового holdout;
- `reports/candidate_leaderboard.csv` — таблица отбора кандидатов;
- `reports/model_selection_summary.md` — текстовые выводы по выбору модели;
- `reports/model_metadata.json` — параметры, признаки, разбиение и версии библиотек;
- `reports/validation_predictions.csv` и `reports/holdout_predictions.csv` — прогнозы;
- `reports/segment_metrics.csv` — качество по основным сегментам;
- `reports/figures/` — диагностические графики.

Каталог `reports/archive/initial_experiment/` сохраняет исходные результаты проекта. Они получены до текущего протокола временной валидации и нужны для истории развития репозитория.

## Ограничения

Модель описывает рынок объявлений 2018–2021 годов и не является актуальной независимой оценкой недвижимости. В исходных данных нет стабильного идентификатора объекта, поэтому повторные публикации одной недвижимости могут встречаться как отдельные записи.
